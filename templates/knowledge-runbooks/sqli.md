# ランブック: SQL インジェクション（D06・D07）

## 意味
- **D06**: DB の構文エラーが出た。攻撃の試み（失敗したもの）か、自分たちのバグ。
- **D07**: 注入らしい形の SQL 文（`UNION SELECT`、`pg_sleep` 等）が実行された。**文字列連結で SQL を組み立てている箇所に、攻撃の入力が届いている**。

## 最初の15分
1. どの API か。Errors Inbox で該当のエラーグループを開き、初めて出た時刻を確認する。
2. 直前のデプロイ（D18 / iRCA）。デプロイ直後なら自分たちのバグの可能性が高い。
3. 同じ API で DB 時間が二山に分かれていないか（D09。時間差を使う攻撃）。
4. 同じ時間帯に D21（RCE の試み）や D20（新しい外部通信）が無いか。

## 判断
| 状況 | 見立て |
|---|---|
| D07 が1件でもある | 注入できる箇所がある。**緊急** |
| D06 がデプロイ直後から | 自分たちのバグの可能性 |
| D06 が少数のユーザーから、多様な形で | 攻撃の試み |

## 封じ込め（承認が必要）
- 該当 API の一時停止、または WAF での遮断
- DB のアカウント権限の確認（読み取り専用にできるか）

## ④ 調査へ
D07 があれば、取得されたデータの範囲を調べる（I01〜I04）。生の SQL は記録していない（`obfuscated`）ので、何が返ったかはアプリのログで確認する。

## 再発防止
- コード監査の F7 を修正する（プレースホルダを使う）。IAST がある環境では、テスト環境で再確認する
