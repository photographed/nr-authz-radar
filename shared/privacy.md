# プライバシーとデータ最小化

> 本ファイルは設計上の注意点の整理であり、**法的助言ではない**。IP アドレス等を送る前に、自社の法務・DPO に確認すること。

## 原則: 検知に必要な最小限だけを New Relic に送る

セキュリティ監視は「多く持つほど良い」ではない。持ったデータは漏えい・目的外利用・保存期間・越境移転のリスクになる。
本プラグインは **既定では IP アドレスを送らない** 設計にし、送る場合は明示的なオプトインにする。

## IP アドレスの位置付け

| 法域 | 位置付け（要点） |
|---|---|
| GDPR（EU） | IP アドレスは **個人データ** として扱われる（他の情報と組み合わせて個人を識別し得るため）。ハッシュ化しても **仮名化データ** であり、個人データのまま |
| 個人情報保護法（日本） | IP 単体は通常、個人情報に当たらないとされるが、**個人関連情報** に当たり得る。他の情報と容易に照合できる場合は個人情報になる |

補足:
- GDPR 前文49では、ネットワーク・情報セキュリティのための処理は **正当な利益** になり得るとされている。つまり「禁止」ではないが、
  目的の限定・保存期間・処理の記録・委託契約（DPA）・越境移転（EU のデータを US リージョンに送る等）の整理が必要になる。
- **単純なハッシュ（SHA-256 等）は IP の匿名化にならない。** IPv4 は約43億通りしかなく、総当たりで元に戻せる。
  ハッシュを使うなら、秘密鍵付きの HMAC（鍵はアプリ側で管理し、定期的に入れ替える）が最低条件。

## New Relic 側の挙動（確認できた範囲）

- **APM エージェントは、既定ではクライアント IP を送らない。**
- **Browser エージェント**: 接続時に IP を一時的に取得し、国・地域・都市・ASN 等の付加情報を得るために使う。
  既定設定では GDPR / CCPA が定義する個人データを保持しない、と説明されている（保持期間・マスク方法の詳細は未確認）。
- ログやヘッダーをそのまま送ると、意図せず IP（`X-Forwarded-For` 等）やメールアドレスが入ることがある。
  New Relic には、ログの難読化ルール・データの削除ルール（drop rules）・High-security mode などの抑止手段がある。

## 本プラグインの推奨レベル

| レベル | 送るもの | 使える検知 | 推奨 |
|---|---|---|---|
| **L0（既定）** | IP は送らない。代わりに `client.asn`・`client.country`・`edge.verdict`（WAF / CDN の判定結果） | D11・D14 を ASN と国の粒度で実行（精度は下がる） | ✅ 既定 |
| L1（オプトイン） | `client.ip_hmac`: 秘密鍵付き HMAC。鍵は **日次で入れ替える**（日をまたいだ追跡をできなくする） | D11・D14 を IP の粒度で実行 | ⚠️ 法務確認のうえで |
| L2 | 生の IP | — | ❌ 推奨しない |

**IP の粒度が必要な分析は、IP を既に正当に扱っているエッジ（WAF / CDN / ロードバランサー）側で行い、
New Relic には判定結果（`edge.verdict`、bot スコア等）だけを渡す**のが、多くの場合もっとも安全で効果的。

## Skill の振る舞い

- `nr-appsec-guard` の推奨では L0 を既定とし、L1 を提案するときは必ず本ファイルの注意点を添える。
- Readiness 監査（R11）で、**すでに送られてしまっている個人データ**（生 IP、メールアドレス、生 SQL など）を検出し、改善項目として報告する。
- レポートには、ユーザー ID・IP・メールアドレス等を生の値で載せない（件数・上位N件の要約・ハッシュ値の先頭のみ）。
