# ランブック: RCE の兆候（D21・D20）

## 意味
- **D21**: RCE の試みで出る特有の例外（デシリアライズ・式言語・JNDI・コマンド起動の失敗）が出た。**失敗した試み**の痕跡。
- **D20**（Hunt で確認）: 見たことのない外部の宛先への通信。D21 と同じ時間帯なら、**試みが成功した可能性**がある。

## 最初の15分
1. D21 の API と例外の種類（Errors Inbox）。
2. **D20 を実行する**（新しい外部の宛先。攻撃の確認によく使われるサービスや IP 直指定の宛先が無いか）。
3. 直前のデプロイ（D18 / iRCA）。
4. Infrastructure がある場合、同じホストで不審なプロセスや CPU の急増が無いか。

## 判断
| 状況 | 見立て |
|---|---|
| D21 のみ | 攻撃の試み。脆弱な箇所があるかをコード監査（F9・F10）で確認 |
| D21 と D20 が同時 | **侵入の可能性。最優先** |
| D20 のみ | 正当な連携の追加か確認（デプロイ記録） |

## 封じ込め（承認が必要）
- 該当ホストのネットワーク隔離、外向き通信の遮断
- 該当 API の停止
- 認証情報（DB・クラウド・API キー）の入れ替え

## ④ 調査へ
侵入の可能性がある場合は、New Relic の範囲を超える（OS・ネットワークのログ、EDR）。社内のインシデント対応の手順に引き継ぐ。
APM の調査（I01〜I04）は、侵入の入口になった API と時刻の特定に使う。

## 再発防止
- コード監査の F9・F10 を修正する。IAST がある環境では、テスト環境で再確認する
- 外向き通信を許可リストで制限する
