# 生成しなかったアラート（現在の段階: S0）

## 推奨: これを満たすと追加できるアラート

| 検知 | 名前 | 証拠の強さ | 必要なこと |
|---|---|---|---|
| D01 | IDOR 成功の証拠 | 証拠 | 段階 S2 が必要（現在 S0） |
| D02 | 他人のリソースへのアクセス試行 | 強い兆候 | 段階 S2 が必要（現在 S0） |
| D03 | ID 列挙 | 異常 | 段階 S1 が必要（現在 S0） |
| D11 | 少数アカウント × 多数のネットワーク | 異常 | 段階 S3 が必要（現在 S0） |
| D12 | ブラウザを経由しない API 直叩き | 異常 | データソースが必要: Browser + 分散トレーシング |
| D22 | 認可拒否の急増（方式に依存しない） | 異常 | 段階 S2 が必要（現在 S0） |
| D23 | 1リクエストで大量の所有者照合 | 強い兆候 | 段階 S3 が必要（現在 S0） |

## 異常の検知（既定では通知しない）

量や割合の変化は偽陽性が多いため、既定では生成しない。`--include-anomaly` で、通知しない別のポリシーに入れて日次で確認できる。

- D04 403 / 404 比率の急上昇
- D10 認証失敗の急増

## アラートにしない検知（Hunt で確認する）

| 検知 | 理由 |
|---|---|
| D05 | S3 の属性が必要で、しきい値が組織ごとに大きく異なるため Hunt で確認する |
| D08 | 平常時との比較（COMPARE WITH）が必要で、アラート条件にできない |
| D09 | 分布の形（二山）を見る判定で、単純なしきい値にできない |
| D13 | 入れ子のクエリを使うため、アラート条件にできない可能性が高い |
| D14 | 平常時との比較が必要 |
| D15 | 攻撃の兆候ではなく設定のリスク（定期レポート向け） |
| D17 | 「初めて出現した」の判定（earliest）が必要 |
| D18 | 相関のための参照クエリ |
| D20 | 「初めて出現した宛先」の判定（earliest）が必要。D21 の発火時に Hunt で確認する |
